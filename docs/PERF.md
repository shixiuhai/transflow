# 性能基准

> 环境：Chrome for Testing 159（headless）、Linux、mock 渠道（每批 80ms 延迟）、fixture 7 段。
> 命令：`pnpm smoke`（输出 `first block` / `cache hit` / `1,000 block` 三行）。

| 指标 | 目标 | mock 基线 | 说明 |
|---|---|---|---|
| 首段出现 | ≤800ms | **146ms** | 含一次 80ms mock 请求 + DOM 插入 |
| 整页 7 段 | ≤1s | **146ms** | mock 单批返回，首段≈整页 |
| 缓存命中整页 | ≤300ms | **27ms** | 0 网络请求，仅 DOM 插入 |
| 1,000 块插入（含强制布局） | ≤120ms | **76ms** | `div.tf-block` + 文本 + layout |
| zip 体积 | <800KB | **104KB** | 含 5 个尺寸图标 |

## 真实火山渠道（2026-11-25）

环境：本机服务器（带 VPN/代理出口），Chrome for Testing 159 headless，fixture 7 段，`volc:e2e`。

| 指标 | 实测 |
|---|---|
| 首段出现 | **875ms** |
| 整页 7 段 | **877ms** |
| 单段直连 API（5 次中位数） | **1336ms**（1129–4158ms） |
| 16 段批量（3 次中位数） | **859ms**（567–1244ms） |
| 用量记录 | 480 字符（volc） |
| 译文样例 | “快速世界中的慢阅读” / “我们被告知速度是一种美德…” |

> 网络说明：本机到火山经过代理，单段 1.1–4.2s 波动明显；国内家庭宽带/办公网直连应显著低于此值。首段 875ms 已接近 800ms 目标，页面只发 1 批（7 段）所以首段≈整页；长文会体现“首段先出、后续补齐”。

复现：

```bash
pnpm volc:check   # 直连 API 测试 + 两句样例
pnpm volc:bench   # 单段 / 16 段批量延迟
pnpm volc:e2e     # 扩展端到端：首段/整页/截图
```

## 说明

- mock 渠道固定 80ms/批，因此首段与整页时间接近；真实渠道下首段会明显早于整页（视口优先 + 分批）。
- 1,000 块基准直接调用 DOM 插入模式（与 `renderBlock` 相同），并强制一次布局，排除网络因素。
- 目标值来自 `01-UI-Fusion深度分析与定稿.md` / `00-调研与重构方案.md`。
